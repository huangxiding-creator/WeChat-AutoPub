# WeChat-AutoPub —— 微信公众号草稿·贴图全自动发布系统

> 每天上午自动运行：三层冗余定时触发 → 三账号串行登录 → 草稿箱文章/贴图发布 → 发表记录贴图触发 → 金标准验证 → 收工关闭浏览器 → **自复盘迭代改进**。全程拟人节奏、零删除零编辑、多级熔断护栏、单点故障自愈。

## 功能总览

| 功能 | 说明 |
|---|---|
| 📝 草稿自动发布 | 草稿箱最近 N 天（默认 3 天）文章与贴图：**贴图不限日期全发**，文章按天数窗口过滤；文章篇间 1.5~2.5 分钟、贴图 20~50 秒随机间隔 |
| 🖼 贴图触发发布 | 扫「发表记录」前 5 页的「已自动生成贴图草稿」→ 触发生成 → 保存落箱 → 从草稿箱发表 |
| 👥 三账号串行 | 多账号一个一个处理（红线：绝不并行登录两个公众号），cookie 复用免扫码 |
| 🔍 启动登录预检 | 每次运行先逐档案核登录态：有效→直接跑；失效→一键「登录」免扫码恢复；仍失效→企微提醒+二维码当场等扫（等待期零刷新），扫完才进发布；超时未扫→跳过该档案不断链 |
| ⚡ 登录保活 | 每日 **23:00 睡前刷新会话**（隔夜失效主战场：最新鲜 cookie 带过夜，平台按活跃续期即免扫码）+ **07:00 晨检**（一键恢复救不回的提前 2 小时企微预警）；与主运行共用单实例锁，撞车让路 |
| ⏰ 四任务冗余定时 | **四任务异名差异化 `--trigger` 埋点**（每日 09:00 主 + 每日 11:37 备 + 每次登录兜底 + 保活 07:00/23:00）同命令触发，单点被清照跑不误；幂等防重（单实例锁 + 当日完成证据，重复触发数秒安全退出）；每次运行自动自愈补装被清任务；窗口内随机时刻启动；触发来源可观测（复盘据此给值守打分） |
| ✅ 金标准验证 | 「草稿从草稿箱消失」才算发布成功——发表记录按标题核对必然假阳性（贴图与源文章同名） |
| 🧹 收工收口 | 运行结束自动关闭工具打开的所有浏览器（按 profile 精准识别，**不碰用户自己的浏览器**；登录态存磁盘不丢） |
| 🔄 自复盘迭代 | 每日收官后自动：观测（日志+DB）→ **四维打分（保活登录/安全效率/稳定顺畅/无人值守，各 100 分+逐条扣分证据）** → 诊断 → **有界自调参（双旋钮）** → 报告落盘 → 改进积压 → 低分企微预警，形成持续改进闭环；维护会话消化 risk 发现落码 |
| 📊 战报口径 | 「成功」只算真发布（对齐 DB 台账与金标准）；贴图**触发生成**单独计数，绝不双计 |
| 🤖 拟人节奏 | 每步操作后随机停 1~3 秒；单账号单日发布数熔断（默认 20）；连续失败 3 次熔断 |
| 🧠 最小化运行 | 浏览器窗口全程最小化 + 看门狗每 10 秒纠偏 |

## 系统架构

```
run.py ── 四任务冗余触发（09:00 主 / 11:37 备 / 登录兜底 / 保活巡检，同命令幂等 + 触发来源埋点）
  │  --window 09:00-12:00   进程内随机延时启动
  │  data/run.lock           单实例锁（PID 探活，Windows 安全实现）
  ▼
┌──────────────── orchestrator（账号串行调度）────────────────┐
│  acct05 → acct01 → acct06（逐个：登录→发布→保留登录态退出）    │
└──────────────────────────────────────────────────────────────┘
   │                    │                       │
   ▼                    ▼                       ▼
browser/drafts.py   browser/picposts.py    core/state.py
 草稿箱双轮发布      发表记录贴图触发        publish_records 台账
 （文章轮+贴图轮）    （前5页扫描→保存落箱）  （content_hash 去重）
   │                    │
   ▼                    ▼
browser/session.py ── driver.py（DETACHED 独立 Chrome，
 每账号独立 profile    --user-data-dir + 固定调试端口）
 + 最小化看门狗
  ▼
收官链（run.py finally，无论成败都执行）：
  ① close_project_browsers()  收工关浏览器（精准识别三账号实例）
  ② run_retro()               自复盘：观测→诊断→有界调参→报告
  ③ ensure_installed()        定时任务自愈（被清即补装，明日保险）
  ④ 释放单实例锁

幂等防重（三触发同命令）：单实例锁先于窗口睡眠获取；当日完成证据
（daily_done/<日期>.ok 或当日「运行结束」日志行）让重复触发数秒退出。
```

## 快速开始

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 配置
copy config.example.ini config.ini   # 按需改账号与间隔

# 3. 首跑（每账号先发 1 篇验证链路）
python run.py --mode run --max 1

# 4. 安装每日定时任务（09:00~12:00 窗口随机启动）
python run.py --install-schedule
python run.py --schedule-status     # 查询状态

# 常用
python run.py --mode run            # 立即全量发布
python run.py --retro               # 只跑自复盘（不发布不碰浏览器）
python run.py --recon               # 页面侦察（选择器漂移时存档排查）
```

首跑时浏览器可见并需人工扫码一次；此后 cookie 存于 `data/browser_profiles/<账号>/`，后续运行免扫码。

## 定时可靠性（生产级四层冗余）

> 背景：2026-08-30/31 主定时任务连续两天在触发时刻前后被外部清除（疑似安全软件计划任务清理）。单任务=单点故障，已重构为三层冗余 + 自愈：

| 层 | 任务名 | 触发 | 兜底场景 |
|---|---|---|---|
| 主 | `WeChatAutoPub_Daily_0900` | 每日 09:00 | 正常日 |
| 备 | `WeChatAutoPub_Backup_1137` | 每日 11:37 | 主任务被清/失败（仍在窗口内） |
| 兜 | `WeChatAutoPub_BootCatchup` | 每次登录 | 早上没开机、白天重启 |
| 保 | `WeChatAutoPub_KeepAlive` | 每日 23:00 + 07:00 | 隔夜 cookie 失效（23:00 睡前刷会话带过夜；07:00 晨检，救不回的提前预警） |

**幂等防重**（四任务同命令、差异化 `--trigger` 埋点，重复触发数秒安全退出）：单实例锁（PID 探活）先于窗口睡眠获取；当日完成证据（`data/daily_done/<日期>.ok` 标记 或 当日日志「运行结束」行）让收官后的重复触发直接退出；当日无证据且锁已释放（如中途崩溃）→ 自动重跑（content_hash 去重 + 金标准验证天然幂等）。

**自愈**：每次运行开始与收官各执行 `ensure_installed()`——任一任务缺失立即补装；只要当天有任一触发成功过，被清任务就会被自动找回。

## 每日自动流程

1. **09:00~12:00 随机启动**（计划任务触发 → `--window` 随机延时；错过补跑）
2. **启动预检**：逐档案核登录态——失效的当场弹码等扫（企微提醒，等待期零刷新），扫完才进发布；超时未扫跳过该档案（不断链）
3. **三账号串行**：cookie 免扫码登录 → 草稿箱文章轮（3 天窗口）→ 贴图触发扫描（前 5 页）→ 贴图轮（全发）→ 保留登录态退出
4. **每篇发布**：点卡片「发表」→ 编辑器确认链（安静期判据）→ 金标准验证（草稿从箱中消失）
5. **收官链**：关闭工具浏览器 → 自复盘 → 释放锁
6. 全程日志 `data/logs/autopub.log`；台账 `data/state.db`（publish_records 表）
7. **夜间保活**：23:00 逐号刷新会话带过夜 + 07:00 晨检（失效提前 2 小时企微预警）

## 自复盘迭代机制

每日收官后自动执行（`run.py --retro` 可手动触发）——**自评分 → 自调参 →
自告警 → 自愈的四重闭环**：

```
autopub.log + state.db + schtasks 在位查询
   → 事件流解析（parse.py，含日志级别分级归因）
   → 单日指标 DayMetrics（金标准/流程耗时(文章·贴图分离)/漂移/空轮
     /免扫码·扫码·一键恢复·预检·保活巡检/触发来源/错误分级/幂等让路…）
   → 四维得分卡（scores.py：保活登录/安全效率/稳定顺畅/无人值守，
     各 100 分，逐条扣分证据=与 100 分差距清单）
   → 诊断规则（rules.py）→ ① 发现清单（risk/warn/info 三级）
                          → ② 双旋钮调参决策（有界、证据驱动）
   → 安全写回（tuner.py：键级硬边界复核 → 备份 .bak → 写入 → 重载校验 → 失败回滚）
   → 报告落盘（data/retro/YYYY-MM-DD.md 含四维得分卡 + trend.csv 同日幂等去重）
   → 改进积压（backlog.md：risk/warn 按日累积账龄，未再现自动消项）
   → 低分预警（四维总分 < [复盘]告警阈值分（默认 80）→ 企微推送扣分明细）
```

**四维打分口径**（每维 100 分起步，只做有证据的扣分）：

| 维度 | 主要扣分项 |
|---|---|
| 保活登录 | 人工扫码 -12/次、登录超时 -20、预检失效未救回 -10、保活晨检失效 -15 |
| 安全效率 | 文章单篇>180s 线性计分（900s 归零）、贴图>60s 同理、弹窗风控信号 -8、间隔越界 -5/条 |
| 稳定顺畅 | 台账失败 -10、真实 ERROR -8（设计内让路已剔除）、漂移 -3/条、空轮超常态 -2/轮、账实不符 -10 |
| 无人值守 | 人工扫码介入 -10/次、无定时启动证据 -15、定时任务缺失 -25/个 |

**护栏设计**（自动改进永远不越安全边界）：

- 自动旋钮仅两个：`选择弹窗等待秒`（界 12~40，±5）与 `贴图渲染宽限秒`
  （界 3~15，±2，超时证据 +2 / 三日零超时 -2）；
- **拟人间隔（风控核心）永不自动调整**；
- 出现「发表按钮未找到」等**等待不足证据立即 +5 回撤**（自愈）；
- 越界的人工设定值视为有意覆盖，只提示不改；调参写前二次硬边界复核；
- 写回前备份 `config.ini.bak`，重载校验失败自动回滚；
- trend.csv **同日幂等去重**（主运行+补跑双收官不重复记行），旧表头自动迁移；
- risk 级发现（选择器漂移/会话重置/登录超时）**只报告不自动改码**——进入
  改进积压，由维护会话（Claude Code）消化报告后落生产代码，保证改动经过
  测试与人审。

## 安全设计（红线）

| 红线 | 实现 |
|---|---|
| **永不删除/编辑公众号内容** | `safety.assert_button_safe` 白名单断言，删除类按钮文本直接拒绝 |
| **账号一个一个处理** | orchestrator 串行循环，单账号完成才切下一个 |
| **操作不过快** | 每步 `human_pause()` 随机 1~3 秒；篇间随机间隔（文章 90~150s / 贴图 20~50s） |
| **防风控熔断** | 单账号单日上限（20）；连续失败 3 次停手防原地打转 |
| **绝不重复发布** | content_hash 台账去重 + 金标准验证 + 「未消失=失败，次日自然重试」天然幂等 |
| **发布真伪判定** | 只认「草稿从草稿箱消失」（发表记录标题核对对贴图必假阳性） |
| **浏览器不误伤** | 收工只关 `--user-data-dir` 含本项目 profile 的实例（三重判据精准识别） |
