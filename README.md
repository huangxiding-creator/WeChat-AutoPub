# WeChat-AutoPub —— 微信公众号草稿·贴图全自动发布系统

> 每天上午自动运行：三账号串行登录 → 草稿箱文章/贴图发布 → 发表记录贴图触发 → 金标准验证 → 收工关闭浏览器 → **自复盘迭代改进**。全程拟人节奏、零删除零编辑、多级熔断护栏。

## 功能总览

| 功能 | 说明 |
|---|---|
| 📝 草稿自动发布 | 草稿箱最近 N 天（默认 3 天）文章与贴图：**贴图不限日期全发**，文章按天数窗口过滤；文章篇间 1.5~2.5 分钟、贴图 20~50 秒随机间隔 |
| 🖼 贴图触发发布 | 扫「发表记录」前 5 页的「已自动生成贴图草稿」→ 触发生成 → 保存落箱 → 从草稿箱发表 |
| 👥 三账号串行 | 多账号一个一个处理（红线：绝不并行登录两个公众号），cookie 复用免扫码 |
| ⏰ 窗口化定时 | 每天 09:00~12:00 窗口内**随机时刻**启动；错过补跑（电脑重启/休眠后自动执行）；单实例锁防双开 |
| ✅ 金标准验证 | 「草稿从草稿箱消失」才算发布成功——发表记录按标题核对必然假阳性（贴图与源文章同名） |
| 🧹 收工收口 | 运行结束自动关闭工具打开的所有浏览器（按 profile 精准识别，**不碰用户自己的浏览器**；登录态存磁盘不丢） |
| 🔄 自复盘迭代 | 每日收官后自动：观测（日志+DB）→ 诊断 → **有界自调参** → 报告落盘，形成持续改进闭环 |
| 🤖 拟人节奏 | 每步操作后随机停 1~3 秒；单账号单日发布数熔断（默认 20）；连续失败 3 次熔断 |
| 🧠 最小化运行 | 浏览器窗口全程最小化 + 看门狗每 10 秒纠偏 |

## 系统架构

```
run.py ── 计划任务 WeChatAutoPub_Daily_0900（09:00 触发）
  │  --window 09:00-12:00   进程内随机延时启动
  │  data/run.lock           单实例锁（PID 探活，Windows 安全实现）
  ▼
┌──────────────── orchestrator（账号串行调度）────────────────┐
│  acct05 → acct01 → acct06（逐个：登录→发布→保留登录态退出）    │
└──────────────────────────────────────────────────────────────┘
   │                    │                       │
   ▼                    ▼                       ▼
browser/drafts.py   browser/picposts.py    core/state.py
 草稿箱双轮发布      发表记录贴图触发        publish_records 台账
 （文章轮+贴图轮）    （前5页扫描→保存落箱）  （content_hash 去重）
   │                    │
   ▼                    ▼
browser/session.py ── driver.py（DETACHED 独立 Chrome，
 每账号独立 profile    --user-data-dir + 固定调试端口）
 + 最小化看门狗
  ▼
收官链（run.py finally，无论成败都执行）：
  ① close_project_browsers()  收工关浏览器（精准识别三账号实例）
  ② run_retro()               自复盘：观测→诊断→有界调参→报告
  ③ 释放单实例锁
```

## 快速开始

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 配置
copy config.example.ini config.ini   # 按需改账号与间隔

# 3. 首跑（每账号先发 1 篇验证链路）
python run.py --mode run --max 1

# 4. 安装每日定时任务（09:00~12:00 窗口随机启动）
python run.py --install-schedule
python run.py --schedule-status     # 查询状态

# 常用
python run.py --mode run            # 立即全量发布
python run.py --retro               # 只跑自复盘（不发布不碰浏览器）
python run.py --recon               # 页面侦察（选择器漂移时存档排查）
```

首跑时浏览器可见并需人工扫码一次；此后 cookie 存于 `data/browser_profiles/<账号>/`，后续运行免扫码。

`config.ini` 全部键（中文键名，模板见 `config.example.ini`）：

```ini

登录等待扫码超时分钟 = 30

[草稿]

每篇间隔最大秒 = 150
选择弹窗等待秒 = 25             # ★ 自复盘可调（界 12~40）
安静期秒 = 8                    # ★ 自复盘可调（界 5~15）
空轮重试上限 = 2                # ★ 自复盘可调（界 1~3）

[贴图]

[定时]

最晚运行时间 = 12:00
错过补跑 = 是                   # 错过计划时刻（重启/休眠）后开机补跑
仅工作日 = 否

[浏览器]
Profile根目录 = data/browser_profiles
浏览器路径 =                    # 留空自动探测 Chrome/Edge
无头模式 = 否                   # 需扫码场景必须可见
运行结束关闭浏览器 = 是          # 收工收口（只关工具 profile 的实例）
```

★ 标记键为**自复盘自动调参目标**：只在硬边界内逐日小幅（±5/±1）调整，越界人工设定值一律不动。

## 每日自动流程

1. **09:00~12:00 随机启动**（计划任务触发 → `--window` 随机延时；错过补跑）
2. **三账号串行**：cookie 免扫码登录 → 草稿箱文章轮（3 天窗口）→ 贴图触发扫描（前 5 页）→ 贴图轮（全发）→ 保留登录态退出
3. **每篇发布**：点卡片「发表」→ 编辑器确认链（安静期判据）→ 金标准验证（草稿从箱中消失）
4. **收官链**：关闭工具浏览器 → 自复盘 → 释放锁
5. 全程日志 `data/logs/autopub.log`；台账 `data/state.db`（publish_records 表）

## 自复盘迭代机制

每日收官后自动执行（`run.py --retro` 可手动触发）：

```
autopub.log + state.db
   → 事件流解析（parse.py）
   → 单日指标 DayMetrics（金标准数/流程耗时/弹窗出现/漂移告警/空轮开销…）
   → 诊断规则（rules.py）→ ① 发现清单（risk/warn/info 三级）
                          → ② 调参决策（有界、单旋钮、证据驱动）
   → 安全写回（tuner.py：备份 .bak → 写入 → 重载校验 → 失败回滚）
   → 报告落盘（data/retro/2026-08-30.md + trend.csv 趋势累积）
```

**护栏设计**（自动改进永远不越安全边界）：

- 只自动调 `选择弹窗等待秒` 一个旋钮，界 12~40，逐日 ±5；
- 出现「发表按钮未找到」等**等待不足证据立即 +5 回撤**（自愈）；
- 越界的人工设定值视为有意覆盖，只提示不改；
- 写回前备份 `config.ini.bak`，重载校验失败自动回滚；
- risk 级发现（选择器漂移/会话重置）**只报告不自动改码**——由维护会话
  （Claude Code）消化报告后落生产代码，保证改动经过测试与人审。

趋势样例（`data/retro/trend.csv`）：

```csv
date,accounts_done,db_published,db_failed,gold_pass,flow_mean_s,gap_article_mean_s,picker_seen,selector_drift,session_lost,empty_breaks,tuned
2026-08-30,3,34,2,34,690.8,187.3,0,103,0,8,picker:25->20
```

## 安全设计（红线）

| 红线 | 实现 |
|---|---|
| **永不删除/编辑公众号内容** | `safety.assert_button_safe` 白名单断言，删除类按钮文本直接拒绝 |
| **账号一个一个处理** | orchestrator 串行循环，单账号完成才切下一个 |
| **操作不过快** | 每步 `human_pause()` 随机 1~3 秒；篇间随机间隔（文章 90~150s / 贴图 20~50s） |
| **防风控熔断** | 单账号单日上限（20）；连续失败 3 次停手防原地打转 |
| **绝不重复发布** | content_hash 台账去重 + 金标准验证 + 「未消失=失败，次日自然重试」天然幂等 |
| **发布真伪判定** | 只认「草稿从草稿箱消失」（发表记录标题核对对贴图必假阳性） |
| **浏览器不误伤** | 收工只关 `--user-data-dir` 含本项目 profile 的实例（三重判据精准识别） |

## 故障排查

| 症状 | 处置 |
|---|---|
| 日志大量「选择器可能漂移」 | `python run.py --recon` 存档页面结构，维护会话更新选择器 |
| 提示需重新扫码 | cookie 失效：手动打开浏览器跑一次可见模式扫码 |
| 定时任务没跑 | `python run.py --schedule-status`；被安全软件清理则重装 `--install-schedule` |
| 双开保护误触发 | 检查 `data/run.lock` 内 PID 是否真存活（工具会自动清理死锁） |
| 推送 GitHub 代理断连 | `git -c http.proxy= -c https.proxy= push` 直连兜底 |
| 企微通知被拒 errcode 40058 | 单日结果超多时 markdown 超 4096 字上限（已知，后续版本加截断） |
